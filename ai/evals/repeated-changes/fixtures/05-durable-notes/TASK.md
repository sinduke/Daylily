Connect the note API to an application-owned durable JSON file repository. Complete NoteRepository and NotesApp across Repository.swift and Routes.swift. NoteRepository(fileURL:) must load an existing JSON array of Note; a missing file starts empty, but malformed or unreadable existing storage must throw instead of silently discarding data. create(text:) trims surrounding whitespace, rejects empty text with HTTP 400, allocates unique increasing integer IDs, atomically persists the complete new array to fileURL, and only publishes in-memory state after the write succeeds. Parent directories may be created. list() returns ID-ascending notes. NotesApp.application(repository:) exposes GET /notes and POST /notes (input {"text": String}, response Note) with HTTP 200, resolves the supplied actor through a typed DependencyKey and preserves GET /health = "ok". Recreating the repository/application at the same file must preserve all notes. Storage errors must propagate; do not mask them as an empty successful result. Acceptance includes concurrent writes, reload, whitespace, corrupt storage and write failure. This exercise is file persistence, not a database driver implementation.
