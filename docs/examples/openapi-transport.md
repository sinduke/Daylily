# OpenAPI Schemas and Generated Services

`DaylilyOpenAPI` exports route metadata. `DaylilyOpenAPITransport` connects server
code generated by Apple's Swift OpenAPI Generator to Daylily. Both remain optional
modules; the generator itself is only a dependency of the example consumer.

Register schemas explicitly when route metadata refers to application models:

```swift
import DaylilyCore
import DaylilyJSON
import DaylilyOpenAPI

struct User: Codable, Sendable {
    let name: String
    let roles: [String]
}

var components = OpenAPIComponents()
components.registerSchema(.object(properties: [
    "name": .string(),
    "roles": .array(items: .string(enum: ["reader", "writer"])),
], required: ["name", "roles"]), named: "User")
components.registerSecurityScheme(.bearer(format: "JWT"), named: "bearerAuth")

let app = Application {
    Get("/users/:id") { request in
        let id = try request.parameters.require("id", as: Int.self)
        return JSON(User(name: "User \(id)", roles: ["reader"]))
    }.describe(
        inputs: [.path("id", type: "Int")],
        responses: [.response(.ok, contentType: "application/json", type: "User")],
        security: [.requirement("bearerAuth")]
    )
}
let document = try app.validatedOpenAPI(
    title: "Users", version: "1.0.0", components: components
)
```

The type name `User` in metadata becomes `$ref: #/components/schemas/User`.
Use `.reference("User")` inside another registered schema for composition or
recursive models. Registration is name-based and replaces an existing component
with the same name. It does not inspect Swift declarations. Unknown unregistered
Swift names retain the original `object` plus `x-swift-type` fallback.

Schemas support scalar types, object `properties` and `required`, array `items`,
string enums, and local schema references. Basic, bearer, and API key security
schemes are supported. Security declarations document the contract; applications
still provide authentication middleware. In OpenAPI 3.1, non-OAuth security
requirements may include role names; OpenAPI 3.0 requires empty arrays for these
schemes. See the [OpenAPI security requirement contract](https://spec.openapis.org/oas/v3.1.0.html#security-requirement-object).

Existing `app.openAPI(title:version:)` calls remain nonthrowing. Pass `components:`
to that method and call `document.validate()`, or use `validatedOpenAPI` to fail
before exporting. Validation reports the document location and reason for unknown
security/schema references, malformed component definitions, missing path input
metadata, and duplicate operation IDs. It checks the supported subset, not the
complete OpenAPI/JSON Schema specification. OAuth flows, external references,
nullable unions, and automatic Swift schema derivation are outside this slice.

## Actual generation and HTTP round trip

[`examples/openapi-service`](../../examples/openapi-service) is an independent
SwiftPM package with a real `OpenAPIGenerator` build plugin. Its `ExportSchema`
executable constructs the contract through Daylily runtime metadata and explicit
schemas, validates it, and writes `Sources/GeneratedAPI/openapi.json`. The plugin
generates `APIProtocol`, `Client`, `Components`, and operation types from that file.
The example implements the generated protocol and calls the generated client
through `URLSessionTransport` over a real local HTTP connection.

From the repository root:

```sh
scripts/openapi-smoke-test.sh --mode path
```

The script uses a fresh external package, exports the schema, runs the real
generator, compiles its output, starts Daylily, checks GET path parameters and a
POST JSON body/response including array and enum fields, then gracefully shuts
down the service group and verifies that startup, shutdown, and cleanup each ran
once in order. The script also rejects a stale checked-in specification. The
application owns its `Logger` and `ServiceGroup`;
adapters do not bootstrap global logging or lifecycle state. The HTTP check has a
60-second process deadline. Set `OPENAPI_PORT` to avoid a local port collision.

To generate and run the example directly:

```sh
cd examples/openapi-service
swift run ExportSchema Sources/GeneratedAPI/openapi.json
swift run App --check
swift run App
```

Then call `http://127.0.0.1:18083/api/greetings/Swift` or POST
`{"message":"hello"}` to `/api/echo`. Ctrl-C requests graceful shutdown.

Dependency validation has identical checks in every mode:

```sh
scripts/openapi-smoke-test.sh --mode revision --revision COMMIT_SHA
scripts/openapi-smoke-test.sh --mode release --version EXACT_VERSION
```

Use a commit or release that contains this schema API. Release mode uses an exact
version, and revision mode pins the supplied commit. The script prints the resolved
Daylily revision and rejects a resolved revision or version that differs from the
requested pin. `--keep` preserves the scratch package and generated output for
inspection. A first build downloads and compiles the generator dependencies.

The server transport supports whole-segment parameters such as
`/pets/{petId}` → `/pets/:petId`. Mixed segments such as `/files/{name}.zip`
throw during registration. Request bodies retain their one-shot semantics.
